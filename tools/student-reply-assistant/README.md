# Ответы ученикам · первый локальный прототип

Приёмник новых личных сообщений Telegram → очередь → один отдельный чат Codex → черновик для Ивана. Поддерживает учеников, родителей и новых клиентов. Автоматической отправки нет; транспорт не содержит методов отправки, удаления или отметки прочитанным.

## Что уже сделано

- Отдельный чат с правилами общения и картой платформы; инструкции в `ASSISTANT.md` и `PLATFORM_CONTEXT.md`.
- Официальные Telegram business/secretary updates. Выбор аккаунта и чатов в локальной панели. Отдельный флаг `allPrivateChats: true` включает все текущие и новые личные переписки выбранного аккаунта. При выключенном флаге пустой список ничего не передаёт. Другие владельцы аккаунтов, группы и сообщения ботов отсекаются отдельно.
- Фоновый запуск Windows через `desktop.mjs`: скрытый процесс, зашифрованный сохранённый ключ, повтор подключения после отсутствия сети. Порт `127.0.0.1:5638` предотвращает запуск второго получателя.
- Постоянная локальная очередь, объединение сообщений за 8 секунд, защита от дубликатов, учёт редактирования/удаления. Если Иван ответил во время подготовки, устаревший ответ не сохраняется как актуальный черновик.
- Передача в созданный desktop-чат официальной командой `codex queue`. Проверена 13 ноября на искусственном обращении: чат получил пакет и вернул черновик приёмнику. Используется модель самого чата. Повторная попытка при неизвестной доставке не создаёт дубликат; фактический результат подтверждается отдельной квитанцией с идентификатором пакета.
- Поддерживаемые файлы скачиваются отдельно по обращению, до 20 МБ; фото передаются как изображения. Excel/Python/PDF передаются как локальные файлы для анализа, не запускаются транспортом. Голосовые пока отмечаются как требующие расшифровки.
- Импорт примеров стиля из JSON-экспорта отдельной выбранной личной переписки. Это локальная подборка примеров, не обучение модели и не импорт всех чатов аккаунта.
- Начальный профиль манеры можно сохранить в `private/style-profile.md`: приёмник добавляет его к правилам нового сеанса подготовки. В интерфейсе видно число текстовых примеров; голосовые не считаются изученными.

## Подключение

1. Создать отдельного бота в BotFather и включить Secretary / Business mode. Использовать существующего бота видео-шаблонов нельзя: у него может быть действующий webhook. Прототип проверяет webhook и отказывается его менять.
2. В Telegram подключить бота к своему аккаунту после подтверждения владельца: выбранные личные переписки либо **All Private Chats Except…** без исключений для всех новых обращений. Оставить только **Read Messages**. Reply, Mark as Read, Delete, доступ к профилю, подаркам и историям не нужны.
3. `node cli.mjs init <id-созданного-чата-Codex>` — создаёт только локальные настройки, существующие не перезаписывает.
4. `node cli.mjs serve` — запускает панель только на `127.0.0.1`, порт выбирается автоматически. Приватная ссылка в `private/panel-url.txt`. Открой её в браузере. Ссылка даёт доступ к панели — не пересылай её другим.
5. В панели введи токен нового бота и нажми «Подключить». После успешной проверки на Windows токен сохраняется в `private/bot-token.dpapi`, зашифрованный DPAPI текущего пользователя Windows. В исходниках и настройках открытого токена нет. При следующем запуске поле можно оставить пустым. Альтернатива для CLI — переменная среды `IVAN100_ASSISTANT_BOT_TOKEN`. История сообщений хранится отдельно и этим механизмом не шифруется.
6. После business connection выбери свой аккаунт. Отметь нужные чаты либо «Все личные переписки этого аккаунта, включая новые», сохрани. Новые сообщения **после выбора** попадают в очередь. Старые пропущенные сообщения автоматически не перечитываются.
7. Сначала проверь одно обращение кнопкой «Подготовить в Codex», затем включи автоматическую подготовку. При её включении сообщения разрешённых собеседников, поддерживаемые вложения и примеры стиля передаются в Codex. Панель позволяет менять охват и останавливать приём.

Для постоянного запуска в Windows: `powershell -File install-startup.ps1`. Скрипт создаёт пользовательский `Startup/IVAN100-ReplyAssistant.vbs`, который скрыто запускает `desktop.mjs` при входе в Windows. Он не содержит токена. Для запуска сейчас можно вызвать этот VBS либо `node desktop.mjs`. Повторный запуск не создаёт второй получатель. Приватная ссылка панели обновляется в `private/panel-url.txt`; её нельзя пересылать.

Все `private/*` и `config.local.json` исключены из Git. Эти файлы содержат переписку. На Windows права `0600` не заменяют ACL профиля: размещай рабочую копию в своём пользовательском каталоге и не публикуй её через общий сетевой доступ. Прототип не обещает шифрование истории на диске.

## Стиль переписки

Экспортировать выбранную личную переписку в Telegram Desktop в JSON. Затем:

```powershell
node cli.mjs import-style 'D:/путь/к/выбранному/result.json'
```

Берутся пары «последние сообщения ученика → текстовый ответ владельца выбранного аккаунта». Голосовые и служебные сообщения не считаются текстовыми примерами. Импорт не отправляет ничего в модель; примеры начнут использоваться при подготовке следующего ответа. Не импортируй личные/семейные переписки. До фактического импорта и оценки нельзя говорить, что стиль уже изучен.

Импорт объединяет последовательные короткие ответы, не связывает реплики спустя несколько дней, пропускает пересылки и ответы с кодами доступа/контактными ссылками. Повторный импорт не дублирует одинаковые пары. Старые цены и расписания в примерах не считаются актуальными фактами.

## Библиотека шаблонов «Для себя»

`templateSource` в локальной конфигурации закрепляет единственную группу по числовому `chatId`, имени и `ownerId`. Сначала установить `live:false` и импортировать JSON-экспорт всей группы через `node cli.mjs import-templates 'D:/путь/result.json'`. Текст хранится без переписывания, с темой, датой и метаданными видео/картинок в `private/template-library.json`. Импорт проверяет идентификатор и имя группы, повторный импорт заменяет снимок вместо дублирования.

Для новых сообщений нужен отдельный подтверждённый владельцем доступ бота к **этой** группе. Бот может быть обычным участником с отключённым Privacy Mode; административные права на удаление и управление не нужны. Только после подключения установить `live:true`. Приёмник добавляет `message`/`edited_message` в polling и принимает их исключительно из закреплённой группы. Они обновляют библиотеку, а не создают обращения или автоматические ответы. Другие группы, обычные личные сообщения бота и смена владельца отсекаются.

Следующий черновик получает свежую библиотеку. Помощник сохраняет исходную формулировку подходящего шаблона и просит Ивана вручную переслать нужный гайд с указанием темы, подписи, даты и номера сообщения. Транспорт по-прежнему не имеет send/forward API. Файлы старого экспорта не считаются просмотренными видео. Новые шаблоны и редактирование принимаются при работающем получателе; удаления в обычной группе Telegram не сообщает, поэтому для удаления из библиотеки нужен новый полный импорт. Пропуски при длительном выключении компьютера также восполняются импортом.

## Границы первого прототипа

- Постоянная работа требует включённого компьютера, доступа к Telegram и действующей авторизации Codex. Автозапуск восстановит процесс после входа в Windows, но при выключенном компьютере приёма нет. Telegram хранит необработанные updates ограниченное время, поэтому это ещё не круглосуточный сервис с гарантией доставки.
- Прямой `app-server thread/resume` конфликтует с владельцем desktop-чата. Основной транспорт поэтому использует `codex queue`: отдельный процесс не захватывает чат, а приложение читает очередь само. Ложное успешное завершение по одному коду выхода исключено: приёмник ждёт совпадающую квитанцию с черновиком. Если за четыре минуты квитанция не появилась, автоподготовка приостанавливается, пакет сохраняется; повторной отправки того же пакета нет. Приложение Codex должно быть запущено.
- Один чат отвечает по очереди. Отдельные истории хранятся по ученикам, но сам общий чат Codex видит предыдущие обращения. Строгую техническую изоляцию истории модели дадут отдельные thread на ученика и общий интерфейс очереди — следующий этап.
- Анализ платформы ограничен исходниками и переданными материалами. Приватные production-журналы и состояние сессии ученика пока не подключены. Система не может самостоятельно подтвердить любой баг или исправить сервер.
- Для экспериментального app-server адаптера задаются `read-only` и отсутствие сети. Основной queue-транспорт работает в правах созданного чата приложения; этот чат инструкциями ограничен чтением материалов и записью одного файла результата. Это не техническая песочница. Локальная конфигурация MCP/плагинов Codex может иметь собственные полномочия; перед автоматическим запуском нужно проверить их и отключить лишние. Отдельный технически ограниченный доступ для диагностики предпочтительнее полного доступа разработчика.
- Речь, OCR сложных скриншотов, проверка формул, извлечение вложений из старых экспортов и построение проверенного стилевого профиля требуют следующего этапа и реальных согласованных примеров.
- Совпадение стиля не гарантирует, что собеседник не заметит автоматизацию. Нельзя придумывать личные действия Ивана или ложные ответы на прямой вопрос об использовании помощника. Черновик проверяется Иваном.

## Проверка

`npm test` в этой папке. Тесты используют искусственные сообщения и транспорт без сети: исключение чужих чатов, изоляция очередей, повторные updates, правки/удаление, устаревшие ответы, защита бота с webhook, импорт выбранных текстовых примеров.
