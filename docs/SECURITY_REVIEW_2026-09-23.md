## Требования к следующей установке

Серверная автопроверка Python в production требует Linux, `/usr/bin/python3`, `/usr/bin/bwrap`, `libseccomp.so.2` и разрешённых пространств имён. На текущем Ubuntu-сервере зависимости установлены и проверены. На новом Ubuntu-сервере их устанавливают пакетами `python3 bubblewrap libseccomp2`, затем запускают `node --test server/pythonSandbox.test.js`. Отсутствие зависимости должно исправляться установкой изоляции, а не её отключением.

`PLATFORM_BIND_HOST` оставляют незаданным при локальном nginx. Значение по умолчанию — `127.0.0.1`. Для первого production-запуска с пустым хранилищем требуется собственный `ADMIN_CODE`; секрет не следует добавлять в репозиторий.

## Что остаётся усилить отдельно

1. **Процесс Node сейчас работает от root.** Следующий инфраструктурный этап — отдельный системный пользователь без входа в систему, каталоги приложения вне `/root`, минимальные права на данные, отдельное управление PM2/systemd и проверенный откат. Изоляция Python уже снижает риск пользовательского кода, но не заменяет ограничение прав всего приложения. Перенос требует согласованного обслуживания и проверки звонков/записей.
2. **TURN использует постоянные браузерные реквизиты, без явно заданных квот.** Перейти на краткоживущие реквизиты, выдаваемые только авторизованным участникам звонка, хранить общий секрет только на сервере, задать квоты и после перехода отозвать старые ключи. Сам факт доступности реквизитов участнику WebRTC ожидаем; проблема — длительный срок и отсутствие ограничений. Текущий звонок не перенастраивался во время этой проверки.
3. **Обновления ОС и восстановление резервных копий.** На сервере есть ожидающие системные обновления. Устанавливать с проверкой совместимости и запланированным перезапуском при необходимости; отдельно провести восстановление копии на тестовый сервер. Такой тест восстановления не проводился.
4. **Почта отправителя.** Для рассылки кодов лучше отдельный служебный ящик с паролем приложения и собственным восстановлением. Личная почта администратора должна оставаться независимой от ящика рассылки. Создание нового ящика и перенос SMTP в эту проверку не входили.

Секреты, полные IP пользователей и инструкции по эксплуатации уязвимостей в отчёт не включены.
