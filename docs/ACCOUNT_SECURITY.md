# Почта и сессии

В профиле откройте «Активные сессии». Администратор один раз подключает
отправку писем: выбирает Gmail, Яндекс или Mail.ru, вводит адрес отправителя,
пароль приложения почты и свой текущий код входа. Проверяется реальное TLS
соединение SMTP. Адрес отправителя виден получателям, поэтому рекомендуется
отдельный рабочий ящик. Пароли и одноразовые коды нельзя передавать в чат.

Пользователь привязывает свою почту с подтверждением текущего кода входа
и кода из письма. После привязки адрес не возвращается в API профиля
или сессий. Управление сессиями открывается после подтверждения
письмом на всё время текущей авторизованной сессии.
Смена почты требует подтверждения старой и новой почты.

После подключения SMTP все новые и действующие преподаватели при следующем
открытии аккаунта видят обязательный экран привязки почты перед рабочим
пространством. Закрыть его без подтверждения нельзя; доступна кнопка выхода.
Для новых сессий обязательность также проверяет API и сохраняет через
перезапуск. Подключение SMTP не перекрывает уже открытый урок посреди звонка.
Пока SMTP ещё не подключён, блокировка преподавателей не включается.

Для преподавателя привязанная почта также защищает новый вход:
сначала обычный код, затем код письма, если браузер и IP ещё не подтверждены.
Ученикам дополнительный код при входе не требуется.
Доверие действует 30 дней, привязано к HttpOnly cookie и точному IP.
Один общий IP без cookie не даёт доверия. Смена сети/VPN может запросить
код снова. Геолокация по IP не используется как доказательство личности.
Выход/отзыв сессии также снимает доверие связанного с ней браузера.
Вход с кодом из письма также открывает управление сессиями без второго кода.
Вход из уже подтверждённого браузера и сети сохраняет эту возможность.
Подтверждение сохраняется при перезапуске сервера, привязано к сессии
и версии личной почты. Выход, отзыв сессии и смена почты снимают доступ.
Для старых входов преподавателей используется уже сохранённое подтверждение;
вход без такой записи требует однократного подтверждения по почте.

Коды действуют 10 минут, одноразовые, не более 5 неверных попыток.
Есть ограничения повторной отправки и запросов по аккаунту/IP.
Сессия входа не создаётся до успешного дополнительного подтверждения.
Смена кода входа или почты аннулирует незавершённое подтверждение входа.
Ошибки доставки не отключают дополнительную проверку.

Отзыв сессии сохраняется на диск до ответа API и закрывает её WebSocket/SSE
соединения: звонок, совместную доску/код, уведомления и поток расписания.
Активность в списке — время последнего запроса, а не гарантия присутствия.

Администратору доступны разделы «Все аккаунты», «Учителя», «Ученики»
и «Мои устройства». У ученика указан текущий преподаватель из базы,
по его имени также работает поиск. Фильтры и сведения о преподавателе
не дают другим ролям доступа к чужим сессиям.

## Хранение и эксплуатация

- Каталог: `<PLATFORM_DATA_DIR>/account-security`; можно переопределить
  через `ACCOUNT_SECURITY_DIR`. Он не должен быть доступен через HTTP.
- `accounts.json` содержит зашифрованные адреса и SMTP-пароль, HMAC кодов,
  хеши доверенных браузеров/IP и ограничения попыток; не plaintext секреты.
- `encryption.key` — ключ AES-256-GCM, права 0600. Резервировать вместе с
  accounts.json, отдельно от публичных файлов. Потеря ключа делает почту
  и настройки SMTP нечитаемыми. Доступ к обоим файлам раскрывает секреты.
- SMTP: порт 465, TLS с проверкой сертификата, только заданные сервисы.
  Сначала проверьте доступность SMTP с сервера Timeweb; учётные данные
  вводятся только в форме сайта. Реальную доставку проверяет привязка почты.
- Первичная привязка опирается на существующий код входа. Рекомендуется
  привязать почту владельца до передачи доступа к аккаунту другим людям.
- Потеря почты требует ручного восстановления администратором сервера после
  проверки владельца; публичного обхода OTP, универсального кода или
  вывода кодов в логи нет. Перезапуск не снимает защиту входа и лимиты.
- Доверенный IP берётся из Express `req.ip` за настроенным proxy boundary;
  в production backend должен принимать внешний трафик только через nginx.
