# Индивидуальный этап в общем плане

Общий маршрут преподавателя остаётся в `ege-study-plans.json`. В `student-study-progress.json` сохраняются отдельные записи по паре преподаватель/ученик: связи страниц с темами и частями, текущая страница, выбранная задача, завершённые части и версия записи. Перевод ученика другому преподавателю не открывает предыдущие отметки.

## Работа преподавателя

1. На доске открыть нужную страницу и нажать «План». Указать тему и часть; номера из названия страницы или подготовленного набора используются только как подсказка.
2. «Связать страницу» сохраняет привязку без смены этапа. «Сейчас проходим» явно делает страницу текущей. Старые страницы можно просматривать для повторения без смены темы.
3. Выбранная подготовленная задача автоматически запоминается, если она относится к текущей теме и части на текущей странице. Переход к набору другой темы требует новой явной отметки.
4. «Завершить текущую часть» либо «Вся тема пройдена» сохраняет результат и предлагает следующий этап по порядку общего плана. Предыдущие этапы автоматически пройденными не считаются. Можно выбрать существующую страницу либо создать новую.
5. В списке учеников, расписании и календарном занятии доступны текущая тема и «Продолжить». Переход восстанавливает общий выбор страницы доски/кода и выбранную задачу. Содержимое и старые вкладки кода сохраняются.
6. На холсте выбрать ученика: зелёные блоки пройдены, фиолетовый блок изучается, остальные впереди. Порядок и названия блоков по-прежнему общие для всех учеников.

Удалённая страница не заменяется молча первой страницей: предлагается выбрать другую. Переименование сохраняет связь по идентификатору. Редактирование защищено версией; чужие ученики недоступны. Один общий запрос загружает краткие сведения по ученикам, без отдельного запроса на каждую строку и без постоянного опроса.

Эта версия отслеживает личные доски учеников. Общий этап мини-группы не назначается каждому участнику автоматически.

## Проверки

37 тестов: API и хранение нового этапа, изоляция преподавателей, конфликт версий, порядок частей, связывание существующих страниц, переименование/удаление, переход к сохранённой странице и задаче, общий план, каталог страниц, сохранение кода и очередь нескольких наборов. Новые модули проходят ESLint; изменённые большие компоненты не добавляют диагностик к исходному состоянию. Production-сборка проверяет конфигурацию звонка штатным скриптом.

Встроенный браузер использован для проверки выбора ученика, окна связи страницы, завершения части, подсказки следующей темы и создания страницы. В локальном окружении соединение совместного редактора во встроенном браузере не восстановилось; Yjs-синхронизация тех же тестовых страниц и кода отдельно проверена через WebSocket, а переход страницы/задачи — тестом клиентской навигации.
