# Переход на личный ключ автооплаты

Существующие ученики, привязки плательщиков, ставки и оплаченные уроки сохраняются.
Повторно создавать их не нужно. Историю переводов эта настройка не пересчитывает.

## Для владельца с уже работающим MacroDroid

1. Откройте `ivan100.ru` под своим учительским кодом и обновите страницу.
2. В меню выберите **Управление → Финансы → Автооплата**.
3. Нажмите **Создать личный ключ**, затем **Скопировать тело запроса**.
   Удобно открыть сайт на телефоне: текст сразу окажется в буфере телефона.
4. Откройте свой существующий макрос MacroDroid. Нажмите действие
   **HTTP-запрос (POST) → Настроить → Тело сообщения**.
5. Полностью замените старый текст скопированным JSON. Не меняйте переменные
   `{not_title}` и `{notification}`. Тип сообщения должен быть `application/json`.
   Метод POST, адрес сайта и триггер банковских уведомлений оставьте прежними.
6. Сохраните действие галочкой и сохраните сам макрос.
7. Нажмите на HTTP-действие и выберите **Тестировать действие**.
   В системном журнале MacroDroid ожидается **HTTP response code: 200**.
8. На сайте во вкладке **Автооплата** нажмите кнопку обновления.
   Должны появиться **Личный ключ подключён**, **Подключено** и сообщение
   **Старый ключ отключён**. Тест не должен сделать ни один урок оплаченным.

Перевод денег для этого теста не нужен. Не создавайте второй макрос: оба макроса
будут отправлять одно банковское уведомление. Не пересылайте личный ключ другим людям.
После успешного перехода старое тело запроса больше не работает.

## Для другого преподавателя

Каждый преподаватель создаёт ключ в собственном кабинете. Нельзя копировать тело
запроса владельца: ключ определяет получателя и не может быть перенаправлен чужим
`teacherId`. На сервере отдельные настройки для каждого нового преподавателя не нужны.

В MacroDroid выбирается приложение того банка, в который получает деньги именно
этот преподаватель. Имя плательщика привязывается к своему ученику в разделе
учеников. Отдельно задаётся действующая стоимость занятия. Поддержка текста
конкретного банка зависит от формата уведомления и проверяется по истории.

## Проверка и восстановление

- Если тест вернул не 200, сохраните код и ответ, проверьте полную вставку JSON и
  сохранение макроса. Не отправляйте повторно старые реальные переводы через curl.
- **Создать личный ключ** не отключает старый ключ владельца. Он отключается
  только после первого запроса с личным ключом, включая тест с переменными.
- **Заменить ключ** отключает текущий личный ключ. После этой команды нужно снова
  скопировать тело запроса на телефон. Для первоначального подключения она не нужна.
- Перезапуск PM2 не включает отключённый ключ: настройки хранятся в
  `PLATFORM_DATA_DIR/teacher-payment-connections.json`. Сохраняйте этот файл при
  резервном копировании и переносе сервера.
- Новые уведомления содержат `receiverTeacherId`, `authMode` и идентификатор ключа
  без самого секрета. Для старых записей источник ключа остаётся неизвестным.
- Изоляция учителей не доказывает, за какой урок был перевод, если преподаватель
  ранее отметил оплату вручную. Для таких случаев нужна сверка с банковской выпиской.

## Обновления сервера

Обычный выпуск: обновить код и зависимости, собрать клиент, перезапустить приложение
через `pm2 restart ecosystem.config.cjs --only ege --update-env`, проверить сайт и
выполнить `pm2 save`. Не перезаписывать локальный `ecosystem.config.cjs` и каталог
данных. Текущий переход выполняется скриптом `scripts/release-payment-keys.sh` с
резервной копией, проверками и отказом от перезапуска во время активного урока.
# Совпадающие имена плательщиков

Одно имя отправителя из банка закрепляется за одним учеником в пределах вашего кабинета. При повторном вводе для другого ученика форма показывает прежнего ученика и блокирует привязку и сохранение. Проверка работает также на сервере: регистр, пробелы, точки и «ё/е» не позволяют заменить прежнюю привязку. В разных кабинетах одинаковые имена допустимы.

Если имя введено неверно, сверьте его с банковским уведомлением. Если старая привязка ошибочна или плательщик теперь оплачивает только нового ученика, удалите старую привязку и создайте новую. Это не переносит уже учтённые оплаты.

Если у разных людей одинаковое отображаемое имя или один плательщик оплачивает нескольких учеников, используйте «Включить ручную проверку» рядом с предупреждением. Будущие переводы с этим именем будут требовать проверки, без автоматической оплаты уроков по имени или по найденному в тексте коду. После сверки перевода отметьте оплату нужных занятий в расписании. Кнопка «Продолжить без автопривязки» очищает конфликтующее поле; ученик сохраняется без новой привязки. Ручной режим относится ко всему имени, в том числе к прежнему ученику. Старые оплаты сохраняются.

Вернуть автоматический учёт можно в карточке прежнего ученика после устранения совпадения. Интерфейс просит явно подтвердить, что все будущие переводы с этим именем относятся только к выбранному ученику. Не добавляйте вымышленные буквы или номера: банк их не передаёт.
