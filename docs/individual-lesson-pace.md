# Individual and group lesson pace

Students use the existing mandatory 0–100 pace prompt after conducted individual lessons as well as completed assigned group lessons. Saving closes the prompt only after server confirmation; unanswered lessons remain pending after reload, with another unanswered lesson shown next. Feedback is keyed by lesson and authenticated student, and cannot mark attendance, payments, progress or homework.

Teachers see the last completed lesson's answer, or **Ждём оценку**, and the number of unanswered lessons in **Ученики → Список учеников → Темп уроков**. Clicking opens dated individual and group results with 30-row pagination and refresh. The same history is accessible from the selected student's schedule history. The roster uses one request for all owned students, refreshing every 30 seconds, on focus, online and visibility. Foreign students and deleted students are excluded; the API rejects parent/student access to teacher results. Existing group result panels remain available.

`individual-lesson-pace.json` stores observed individual sessions, starting with the feature's activation timestamp. Native RTC tracking works with recording disabled; Telemost activation and explicit finish are tracked too. Existing real-session observations from homework reminders and completed OBS metadata recover missing observations without changing reminders. Waiting/failed recorder startup alone, calendar-only occurrences, group/listener sessions and connections shorter than one minute do not create individual surveys. Multiple OBS recovery fragments share one lesson identity. An explicit teacher hangup/Telemost finish ends the lesson immediately; an unexpected RTC disconnect has a persisted three-minute grace period. Rejoining cancels that pending completion. Ongoing platform calls, Telemost activity and OBS recording suppress the individual prompt. Historical individual calendar entries are not retroactively turned into surveys; existing group answers and pending requests retain their behavior.

Validation uses temporary data and a controlled clock, including real authenticated HTTP and WebSocket routes, OBS metadata, Telemost, short connection tests, actual restart, response persistence, pagination, teacher/student isolation and group regression. Browser QA uses the actual App, TeacherPanel, ScheduleSection and feedback components with that isolated API. Production checks are in `scripts/check-lesson-pace-release.mjs`; the normal guarded release script runs pace tests, checks exact public bundles and inspects only existing teacher APIs.
