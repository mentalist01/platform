# Повторный отказ записи после занятия: пульт 1.5.32

## Подтверждённая причина

Пульт вызывал `ObsClient.choices()` каждые десять секунд для проверки окон и микрофона. Этот же метод перечислял DirectShow-камеры через `GetInputPropertiesListPropertyItems(video_device_id)`. Установленная виртуальная камера Insta360 Link при каждом перечислении оставляла внутри процесса OBS два открытых дескриптора одного журнала `client_obs64_2026_10_23_.log`.

В процессе OBS 10604 обнаружено 508 открытий этого журнала. OBS одновременно перестал сохранять временные файлы сцен/настроек и начинать следующую запись. Повторный `StartRecord` на простаивающем процессе воспроизвёл отказ, хотя диск имел свободное место и запись в эту папку разрешена. После завершения всех уроков и перезапуска OBS тот же путь снова записывался успешно.

На свежем OBS 25556 пять последовательных запросов списка камер увеличивали число открытых файлов журнала строго `2 → 4 → 6 → 8 → 10 → 12`. Это объясняет задержку до отказа: фоновые проверки постепенно исчерпывали ресурсы процесса, а ручной перезапуск временно освобождал их. Лимит потоков stdio в Microsoft CRT по умолчанию — 512; сообщение OBS о правах/свободном месте здесь не указывало действительную причину.

## Исправление

Список камер хранится на время соединения с OBS. Одновременные запросы разделяют одно перечисление. Пустой список также кешируется; неудачное перечисление можно повторить. После разрыва соединения список запрашивается заново, а закрытие устаревшего сокета не сбрасывает актуальный список.

Кнопка «Обновить камеры» по-прежнему выполняет явное перечисление. Перед началом студийной записи с включённой камерой выполняется обновление для проверки выбранного устройства. Изменение размера/угла камеры и фоновая проверка обычного урока не перечисляют камеры повторно. Окна, микрофоны и мониторы продолжают проверяться как раньше. Драйверы, антивирус и разрешения Windows не изменяются.

## Проверка

- Все 275 существующих и добавленных проверок пульта/пакета проходят; дополнительная проверка переподключения также проходит.
- Регрессионный тест воспроизводит три часа фоновых проверок (1080 циклов): список камер читается один раз, списки окон остаются актуальными.
- Проверены объединение параллельных запросов, повтор после ошибки, кеширование пустого списка, явное обновление и сброс после нового соединения.
- На установленном пульте 1.5.32 проверяется реальный HTTP-маршрут `/choices`, число дескрипторов OBS и несколько последовательных локальных пробных записей. Подробные результаты сохраняются локально в `output/recorder-root-cause-20261023/`.

Ни исходники уроков, ни их идентичности и финансовые данные не меняются. Локальная установка использует штатный механизм смены каталога приложения с резервной копией и проверкой здоровья новой версии.
