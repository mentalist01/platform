# Code summon and individual lesson recordings

The existing teacher-owned board-page command now optionally includes a code solution ID and `view: collab`. It carries no code snapshots. The destination room is derived from the authorized board book and private recipient; a shared group summon cannot point at another pupil's private room. A running editor defers the switch until it can safely select the existing Yjs channel. Existing code-focus restrictions still apply. Accepted selections are remembered before a cold editor mount. Board-only commands retain their previous behavior.

Individual pupils have a new Records navigation entry (`student-recordings`). Group navigation and access to group archives/listening are retained. The library lists own individual lesson history, grouped by month, with topics, dates, Moscow times and publication states. Search and pagination use an owner-authorized `/api/lesson-recordings` endpoint. Listing returns compact metadata; legacy replay files and videos load only after opening a lesson through the existing history-detail route/player. There is no background polling or preloading of video players.

Validation: 24 protocol, selection, history-library and authorization tests; production build. In two isolated browser sessions, a pupil initially viewing Main code moved to the teacher's Explanation 9 tab on summon and could subsequently select Main again without being pulled back. Library search narrowed to the correct topic and opening a ready lesson mounted the existing Rutube player. Fixture data was used; no real pupil work or preferences were changed.
