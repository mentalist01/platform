# Monthly report: constrained window and teacher voice

The report dialog has a fixed header, a keyboard-focusable scrolling content region and a separate footer. Content expansion, textarea resizing, detailed statistics and contact editing cannot push the footer outside the viewport. The footer retains copy/download/send actions and identifies the saved parent contact. The body scrolls independently on desktop and mobile. Focus controls share a row when space allows. Mobile uses the same height constraint and scroll model, with actions in a two-column grid.

Parent-facing focus text speaks directly as the teacher. The automatic and manual Python/EGE/mixed paths never describe stored topic metadata, the platform or automatic generation. Teacher-only controls continue to explain the evidence and permit overrides. Missing, first, unchanged and lower mock results remain distinct; no performance/causality claims are introduced by the copy change.

Validation: browser checks of expanded focus, statistics and contact editing; keyboard access to the bottom of the scroll region; pinned footer and no horizontal overflow on laptop, mobile and short landscape viewports. Existing report/contact tests and a voice regression matrix verify that the message preserves its facts and does not disclose assembly language.
