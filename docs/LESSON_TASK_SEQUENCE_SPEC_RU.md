# Подготовленные задания на доске — ТЗ

Дата: 24 октября 2026 года. Статус: утверждено пользователем; реализация и проверка. Установка после завершения проверки.

## 1. Результат для преподавателя

До урока преподаватель собирает набор: условия, ответы и ссылки на исходные файлы из конспектов. На уроке он выбирает набор и место на доске. Задания появляются по очереди вместе с вложениями и полем проверки ответа. Ручная вставка скриншотов и поиск файлов во время занятия больше не требуются.

Существующий свободный режим доски остаётся доступен. Подготовленные задания можно добавлять на новую или уже существующую страницу.

## 2. Подтверждённые решения

- В индивидуальном уроке ученик и преподаватель работают над одним заданием.
- В группе участники вместе пишут на общей доске, используют одно общее поле ответа и одну очередь заданий. Индивидуальная сдача ответов для каждого участника здесь не нужна.
- Неверный ответ сопровождается сообщением об ошибке и возможностью попробовать снова. Правильный ответ при этом не раскрывается.
- Преподаватель может включить автоматическое добавление следующего задания после верного ответа либо добавлять его сам.
- Преподаватель может пропустить задание, перейти дальше и затем вернуться к пропущенному.
- Название действия для таблиц: «Решать через помощник таблиц».
- Исходный файл выбирается из конспектов и появляется на доске как вложение. Сохранённое решение видно и на доске, и в конспектах.

Обычная доска включена по умолчанию. Набор заданий включается отдельно на выбранной странице; возврат в обычный режим сохраняет рисунки, код, карточки и решения.

## 3. Термины

| Объект | Значение |
| --- | --- |
| Тип задания | Номер ЕГЭ: например, №3, №9, №22. |
| Часть | Настроенная преподавателем часть типа задания. Для №9 и №22 сейчас настроено по две части. |
| Набор | Повторно используемая подготовка: например, «№3 · базы данных · первая практика». |
| Задание в наборе | Один скриншот или несколько изображений условия, правила проверки и вложения. Имеет свой номер в очереди, независимый от номера ЕГЭ. |
| Прохождение | Использование конкретной версии набора на странице индивидуальной или общей групповой доски. |
| Карточка на доске | Размещённое условие с файлами, ответом и состоянием решения. |

Не смешивать «тип ЕГЭ №3» и «третье задание в наборе». В интерфейсе: «ЕГЭ №3 · задача 2 из 8».

## 4. Где преподаватель готовит задания

В конспектах, внутри номера ЕГЭ и нужной части, добавить вкладку «Задания к уроку». Она находится рядом с материалами, из которых выбираются файлы. Дополнительно открыть тот же редактор можно из выбора набора на доске.

Вкладка содержит наборы преподавателя, кнопку «Создать набор», количество готовых заданий и просмотр содержимого. Набор не привязан к одному ученику: его можно использовать на разных индивидуальных и групповых занятиях.

В редакторе набора:

1. Указать название, тип ЕГЭ и часть, если частей несколько.
2. Добавить условия через вставку из буфера, перетаскивание или выбор изображений. Разрешить несколько изображений на одно задание, обрезку, изменение порядка и увеличение для проверки читаемости.
3. Ввести правильный ответ и формат проверки. Ответ доступен только преподавателю.
4. Нажать «Добавить файл из конспектов» и выбрать один или несколько исходных файлов. Файл необязателен.
5. Повторить для остальных заданий; настроить порядок перетаскиванием.
6. Просмотреть «Как увидит ученик» и сохранить набор.

Черновик можно сохранять незаполненным. Для автоматической проверки задание должно иметь условие и корректно заданный ответ. Если проверка автоматом неприменима, преподаватель явно выбирает «Проверяет учитель».

На присланном примере часть изображений содержит текст «Ответ» и «Решение». Условие, которое видит ученик, должно быть подготовлено без этих фрагментов. Предусмотреть просмотр и обрезку перед публикацией. Автоматическое распознавание ответов на изображениях не считать надёжной защитой.

## 5. Создание и открытие страницы

В «Новая страница» предложить «Пустая страница» и «Из набора заданий».

Для набора выбрать тип ЕГЭ → часть при наличии → набор. Название страницы предложить автоматически, разрешить изменить. Существующие страницы не переименовывать и не преобразовывать автоматически.

Страница доски и страница кода сохраняют общую существующую идентичность. Выбранные тип, часть и прохождение относятся к этой странице. Переход между «Доска» и «Код» открывает тот же материал. На уже существующей странице доступно «Добавить набор».

После выбора набора преподаватель нажимает «Выбрать место на доске», указывает точку, видит контур будущей карточки и подтверждает «Добавить первое задание». Esc отменяет размещение без изменения доски. В режиме кода размещение выполняется в видимой части доски.

Добавление второго и следующих заданий не создаёт новую страницу и не очищает рисунки, код, входные данные или результаты запуска. Повторный выбор этого же прохождения открывает сохранённое состояние. Запуск заново — отдельное явное действие, создающее новое прохождение.

## 6. Карточка задания

Карточка содержит:

- Номер ЕГЭ, номер задачи в наборе и состояние: «Решаем», «Решено», «Пропущено».
- Изображения условия с увеличением без изменения качества оригинала.
- Вложения: имя, размер, «Скачать»; для поддерживаемого формата — «Решать через помощник таблиц».
- Общее поле «Ответ» и кнопку «Проверить». Для группы подпись «Общий ответ».
- Сообщение о результате проверки.
- Сохранённые решения: имя файла, автор сохранения, время и действия «Скачать» / «Продолжить решение».

У преподавателя дополнительно доступны очередь, «Следующее задание», «Пропустить и перейти дальше», переключатель автоматического перехода и частный просмотр эталона. Ученику эталон не передаётся.

Условие, вложения и поле ответа образуют перемещаемую группу объектов. Их нельзя случайно разнести при обычном перетаскивании. Преподаватель может изменить размер условия; поле и кнопки должны оставаться читаемыми, в том числе при малом масштабе доски. Ввод в поле не должен рисовать на холсте или запускать горячие клавиши кода.

Рисунки рядом с карточкой остаются редактируемыми. При переносе только карточки они не перемещаются неожиданно. Для переноса вместе с решением — выделение нужных рисунков и карточки либо действие «Выделить задание с записями» с видимой областью выделения.

### Навигация ученика по уже открытым заданиям

Над рабочей областью показать список добавленных задач с номером, кратким названием и состоянием. Ученик может самостоятельно вернуться к любой уже добавленной задаче. Будущие, ещё не добавленные условия ему не раскрываются. Переключение ученика не переключает преподавателя и других участников.

Выбор задачи перемещает к её области на общей доске: это не создание новой страницы и не удаление остальных задач. В индивидуальном и групповом уроке записи под условием могут продолжаться вниз без фиксированной высоты. Условия и записи соседних задач сохраняются.

В режиме «Код + доска» с выбранной задачей открывается связанный вариант кода этой задачи. У каждой задачи собственный код, входные файлы и последний результат запуска; переход между задачами их не заменяет и не обнуляет. Существующий код страницы, не связанный с подготовленным заданием, остаётся отдельным вариантом. Конкретный способ интеграции с лимитами и существующими вкладками нужно проверить до реализации.

Если ученик просматривает более раннюю задачу, показать, какую задачу разбирает преподаватель, и действие «К учителю». Оно возвращает ученика к текущей задаче преподавателя. Обычное добавление задания не отрывает ученика от просмотра или незавершённого ввода.

Проверка: после решения пяти задач ученик открывает 2 → 4 → 1 → 5; на каждом шаге совпадают условие, рисунки, файл, общий ответ и соответствующий код. Дорисовка и изменение кода задачи 2 сохраняются после перехода к задаче 5 и обратно. Навигация ученика не меняет активную задачу в остальных сессиях.

## 7. Ответы и переход дальше

Ответ проверяется сервером, без отправки эталона в браузеры учеников, общий документ доски, журнал воспроизведения или события синхронизации.

Предусмотреть форматы: число; точная строка; последовательность значений с заданным порядком; значения без учёта порядка; несколько полей. Преподаватель видит пример ожидаемого ввода. Пробелы по краям удаляются. Правила ведущих нулей, регистра, разделителей и десятичной запятой задаются форматом, а не универсальным преобразованием всех ответов в число. Для сложных случаев доступна ручная проверка.

Результаты:

- Неверно: «Пока неверно. Попробуйте ещё». Ввод сохраняется, число попыток не ограничивается, следующий шаг автоматически не запускается.
- Верно: «Верно» и состояние «Решено». Повторный запрос проверки не создаёт новое решение и не добавляет ещё одну карточку.
- Пропуск: предыдущая карточка и ввод остаются на доске; статус «Пропущено», следующий шаг доступен. Пропуск не считается верным решением. Можно вернуться и ответить позже.
- Проверка учителем: преподаватель явно подтверждает результат; история отличает ручное подтверждение от автоматической проверки.

По умолчанию переход ручной. Автоматический переход включается преподавателем для конкретного прохождения и виден всем. На правильный ответ добавляется ровно одно следующее задание. Исправление ответа в старой карточке не должно неожиданно переводить текущую очередь вперёд. В конце: «Все задания набора пройдены», отдельно количество решённых и пропущенных.

Поле группы общее: каждый видит один и тот же введённый ответ. На время редактирования отображать «Ответ вводит …», исключить одновременную перезапись текста. Управление переходит после окончания ввода/потери соединения, преподаватель может забрать его. Проверка относится к конкретной версии введённого ответа. Пропуск, изменение режима и порядок задаёт преподаватель.

Результат общей работы хранится как результат группы. Он не превращается в независимое личное решение каждого присутствующего и сам по себе не начисляет каждому личные достижения/опыт. Интеграция с прогрессом и XP обсуждается отдельно.

## 8. Размещение ниже записей

Последовательность развивается вниз от выбранного преподавателем места в координатах доски, независимо от масштаба и положения камеры.

Перед добавлением следующей карточки определить нижнюю границу предыдущих карточек и связанных записей в области работы набора, затем оставить отступ. Если справа или слева есть другое независимое упражнение, оно не должно уводить очередь далеко вниз. Работа поверх старой карточки или далеко за пределами области не должна незаметно включаться в неё.

Чтобы не обещать ненадёжное «угадывание» назначения каждого штриха:

- Показывать преподавателю полупрозрачный контур области текущей работы при размещении и выделении, без постоянной рамки поверх решения.
- Учитывать пересекающие эту область рисунки и расширять её вниз по мере решения.
- В ручном режиме показывать предварительное место следующего задания и разрешать сдвинуть его перед добавлением.
- Если область неоднозначна, автоматическое добавление приостанавливается с действием «Указать место»; ответ и работа уже сохранены.
- При добавлении во время незавершённого штриха дождаться его завершения. Повторно проверить занятость места перед записью операции.

Ранее добавленные карточки и рисунки не передвигаются, чтобы освободить место. Загрузка следующего задания не переключает всем страницу или масштаб и не отрывает камеру от текущего ввода. После добавления видна кнопка «К новому заданию»; существующий призыв учеников остаётся отдельным действием преподавателя.

## 9. Исходные файлы и помощник таблиц

Исходник из конспектов — ссылка на конкретный файл и его версию. Доступ выдаётся только на выбранный файл в контексте задания; соседние папки и чужие личные материалы не раскрываются. Оригинал не перезаписывается решением ученика.

После первого открытия через помощник создаётся решение, привязанное к прохождению, карточке, исходному вложению и владельцу работы. Повторное открытие предлагает продолжить его. «Начать заново» создаёт отдельное решение после явного выбора. Совпадение имён файлов не используется для определения принадлежности.

Ctrl+S сохраняет одну версию решения. На доске и в «Конспекты → нужный тип и часть → Решённые задания» появляются две точки доступа к одному решению, а не две расходящиеся копии. Новая версия обновляет обе. Показывать состояния «Сохраняется», «Сохранено», «Не удалось отправить»; не объявлять сохранение успешным до подтверждения сервера.

Тип ЕГЭ и часть берутся из карточки: для заранее выбранной части не нужно заново спрашивать её после каждого сохранения. Обычные сохранения вне подготовленного задания продолжают использовать существующие настройки частей.

В индивидуальном уроке решение принадлежит ученику; преподаватель может открыть его с соответствующими правами. В группе предлагаем общий итоговый файл: его видят участники, ссылки доступны в конспектах группы/участников, но физически и логически это одна общая работа. Не сохранять файл группы под идентичностью случайно выбранного ученика.

Excel/LibreOffice на разных компьютерах не обеспечивает совместное редактирование одного файла. Поэтому общий файл открывается на запись у одного участника; остальные могут скачать текущую версию или смотреть результат. Для передачи работы — явное действие, сохранение текущей версии и получение новой. Запоздалое сохранение старой локальной копии не затирает более новое: конфликт сохраняется отдельной копией и показывается автору. Новая система не должна требовать перезапуска приложения для передачи права записи.

Цель совместимости — работа с уже установленным помощником через существующий запуск и серверный контекст сохранения. До обещания «переустанавливать ничего не нужно» проверить полный цикл на установленной версии: открыть, сохранить, повторно открыть, получить решение на доске и в конспектах, передать работу в группе. Если протокол требует расширения, сначала согласовать совместимый путь без принудительного обновления у всех учеников.

Любое допустимое вложение можно скачать. «Решать через помощник таблиц» показывается только для реально поддерживаемых помощником форматов. Отсутствие помощника не блокирует просмотр условия, скачивание и ввод ответа; предложить инструкцию установки и загрузку готового решения вручную.

## 10. Сохранность, права и история

- Набор принадлежит преподавателю. Ученик видит только добавленные на его доску условия, вложения и результаты, без эталонов и будущих заданий.
- Запуск набора фиксирует его версию. Редактирование шаблона не изменяет уже начатое или прошлое прохождение. Исправление ошибочного эталона в действующем прохождении — отдельное действие учителя с историей и повторной проверкой сохранённых ответов.
- После перезагрузки восстанавливаются карточки, положение, очередь, режим перехода, ответы, статусы и ссылки на решения. Переключение ученика/группы не переносит к ним предыдущее прохождение.
- Удаление карточки с доски не удаляет файл решения из конспектов. Отмену расположения на доске отделить от отмены уже проверенного ответа/сохранения файла. Удаление и восстановление страницы следует существующим правилам сохранности доски и кода.
- Изменение или архивирование исходника не ломает прошлый урок: удерживать ссылку на использованную версию на время существования прохождения. Явное удаление всех копий и отзыв доступа должны обрабатываться отдельно, без выдачи чужого файла вместо исчезнувшего.
- Смена текущего состава группы не присоединяет нового ученика автоматически к частным данным прошлых участников. Применять существующие правила исторического доступа; предусмотреть доступ к общей работе в контексте конкретного занятия.
- Наблюдатель сохраняет режим только для чтения: не вводит ответ, не проверяет, не меняет очередь и не запускает запись в общий файл. Знание URL не заменяет проверку доступа при скачивании.
- Открытие и решение задач не меняют посещаемость, оплату, финансы, домашние задания и идентичность занятия. Существующая запись урока продолжает работать; новые события должны быть совместимы с воспроизведением, без эталонов и закрытых файлов.

## 11. Технические ориентиры

В текущем проекте уже есть страницы доски/кода (`BoardPagesWorkspace`, `boardPages`, `collabSolutions`), вложения доски (`BoardFiles`), запуск помощника (`useWorkbookHelper`) и серверное сохранение с ревизиями, а также настройки частей (`workbookParts`). Использовать эти механизмы с расширением контекста задания. Групповой владелец файла и общий жизненный цикл проверки потребуют отдельной поддержки: существующего персонального `studentId` для них недостаточно.

Минимальные новые сущности: набор и его версия; задание в наборе; прохождение на странице; экземпляр карточки; попытка проверки; связь решения с карточкой и вложением. У общего файла явно указывается групповой контекст и автор версии. Эталон хранится отдельно от ученического представления.

Критические операции — серверные и повторяемые без дублей: добавить карточку, проверить ответ, перейти дальше, сохранить файл. У одного прохождения и номера в очереди не может оказаться двух карточек после двойного клика, одновременного ответа или повторного подключения. При частичном сбое между созданием карточки и синхронизацией сцены восстановление завершает ту же операцию.

При потере сети введённое значение остаётся черновиком. Переход дальше и статус «Верно» не подтверждаются локально. При возвращении связи не отправлять устаревший ответ поверх нового общего ответа; явно показать конфликт.

Не вводить частый глобальный опрос: использовать существующий канал синхронизации и события изменения решения. Оригиналы изображений и файлы не встраивать в каждую сцену; передавать ссылки, размеры и версии. Предпросмотры загружать по мере необходимости. Повторная проверка ответа не сканирует все конспекты или все файлы. Соблюдать текущие ограничения загрузки, размера сцены и числа страниц; заранее сообщать о превышении без потери предыдущей работы.

## Дополнения 24 октября: ответы и привычный редактор

- Число полей подставляется по существующим правилам банка ЕГЭ; преподаватель может изменить его. Старые однозначные пары/векторы, записанные через пробел, разделяются с резервной копией исходных данных.
- Название задачи показывается без порядкового префикса; для пустого названия используется «Задача N». Перестановка сохраняет название, ответ и вложения одной задачи.
- Вложения из конспектов можно отметить как входные для Python и задать имя, под которым код открывает файл. Файлы подключаются только к связанной вкладке задачи; ручная загрузка файлов работает как прежде.
- Подготовленные задачи используют прежний редактор кода, его вкладки, файлы, отладку и вывод. Вкладка создаётся по стабильному codeId карточки; прежние вкладки и их содержимое не заменяются. Код из первоначальной версии подготовленного режима импортируется один раз и больше не воспроизводится поверх новых правок.
- Навигация доски — одна компактная строка у верхнего края без повторного названия набора. Действия преподавателя раскрываются через «⋯».

## Послеурочные изменения 24 октября

- «Следующее» и «Пропустить» доступны рядом со списком задач; панель участников занимает отдельное место в заголовке. На узкой доске управление переходит на второй ряд.
- Ответ и реальные вложения находятся над условием. Высота карточки измеряется по содержимому, а её проекция меняет только собственную высоту с сохранением позиции и пользовательского размера. Под карточкой остаётся обычный холст. При первом открытии масштаб зависит от ширины, а не высоты условия; дальнейшие переходы сохраняют ручной масштаб.
- Выбранный файл сразу попадает в локальный черновик. Для начатого прохождения есть явная операция обновления только вложений по стабильным ID задач: эталоны, порядок, результаты, код и рисунки не заменяются. Прежние вложения и привязки решений остаются доступны. Конфликтующая версия набора не перезаписывается молча.
- Текстовые вложения TXT/CSV/TSV в №26/27 открываются установленным помощником как исходный текст и отдельная пустая ODS. Исходник выдаётся по scoped-токену, решение сохраняется в карточку и конспекты. Изменения самого помощника не требуются для версии 1.2 и новее.
- Страницы поддерживают один уровень подстраниц с произвольными именами. Пример: основная «26» и восемь частей. Создание через «+» у основной страницы; изменение родителя — через настройку названия страницы. Доска и код используют общий каталог. Вложение меняет только метаданные, идентичности холста и вкладок сохраняются. Удаление родителя не удаляет дочерние работы; восстановление возвращает их группировку. Циклы и вложение подстраницы в подстраницу отклоняются.
- Проверка на изолированных данных включает перенос старой страницы с кодом и рисунком, восемь частей после перезапуска, сохранение общего решения текстового задания и отказ чужому автору файла.

## Уточнения после начала следующего урока

- Дополнение набора после размещения на доске не должно оставлять преподавателя с отключёнными «Следующее»/«Пропустить» без объяснения. При наличии новых ID задач показывается «Подключить ещё N». Операция добавляет только новые задачи, сохраняет прежний снимок и порядок, не меняет открытые карточки, привязки кода, результаты и решения. Повторное подключение не создаёт дублей; изменения чужой или устаревшей версии отклоняются. Сохранение набора отправляет сигнал открытым прохождениям.
- Команда редактора «Сохранить и обновить урок» явно подключает файлы и новые задачи. Она не заменяет условия и эталоны прежних задач.
- Поверх DOM-условий компонуется прозрачный слой обычных штрихов и живого предпросмотра/выделения. Он обрезается границами карточек и не перехватывает события. За пределами карточек обычная отрисовка доски сохраняется, указатели участников располагаются выше условий. Данные рисунков и порядок исходной сцены не переписываются.
- Дерево страниц компактное и свёрнуто по умолчанию; видимая структура не меняет идентичности и общее число страниц. Выбор подстраницы раскрывает её родителя. Ручное сворачивание выбранной ветки допускается, остальные ветки не раскрываются автоматически.

Кнопки помощника, загрузки решения и передачи файла скрыты у учеников. Сервер отклоняет эти операции, включая старые ссылки запуска и сессии помощника, без изменения общего файла. Прежняя ученическая привязка не блокирует открытие преподавателем. Индивидуальные файлы сохраняют прежние права. Скачанная локальная копия не синхронизируется с общим решением.

## Выбор условия и удаление карточки

- «Все задачи» показывает преподавателю весь снимок набора с поиском и предпросмотром условий. Закрытые эталоны в каталог не передаются. У ученика нет доступа к каталогу и управлению очередью.
- Выбор по стабильному ID добавляет только указанную задачу. Повторный выбор переводит к существующей карточке. Ручной и автоматический следующий шаг идут по исходному порядку набора от выбранной задачи; в конце нет перехода к ранее пропущенным условиям.
- Удалённая с холста карточка не блокирует очередь. Продолжение определяется по выбранной видимой карточке; удалённую можно вернуть через список или очередной шаг. Восстанавливаются прежние ID карточки и кода, ответы, статусы и решения. Условие размещается ниже сохранившихся записей, без дубликата и перезаписи кода.
- Повторный клик «Следующее» с прежней исходной карточкой не продвигает очередь ещё раз, включая восстановление без изменения числа карточек.

## Отдельные вопросы, эталоны преподавателя и сохранение подготовки

- Режим «Отдельные вопросы» выбирается у конкретной задачи. Число вопросов от 1 до 50 задаётся явно; формат сравнения применяется к каждому ответу отдельно. Кнопка и результат проверки принадлежат одному вопросу, остальные ответы не проверяются. Задача решена после принятия всех вопросов; автопереход срабатывает один раз. Верные поля защищены от случайной перезаписи, результаты сохраняются между подключениями и перезапусками.
- Эталоны открытых карточек возвращаются только управляющему преподавателю в приватном HTTP-ответе без кэширования. Ученические и наблюдательские проекции, общая сцена, сигналы Yjs и ответы на действия учеников их не содержат. У преподавателя эталон — серый placeholder; при ошибке он также показан рядом с ответом. Значение placeholder не считается введённым ответом.
- «Сохранить и обновить урок» явно применяет режим проверки к уже открытым задачам только при неизменных эталонах. Ответы, ID, код и рисунки сохраняются; старые черновики и права ввода инвалидируются ревизией. Изменение самих эталонов по-прежнему требует новой страницы.
- Автосохранение через 900 мс после изменений принимает неполный набор как черновик. Его ID и ID новых задач стабильны до первого ответа сервера; обновления сериализованы с проверкой версии. Запоздавший ответ не заменяет более новые правки или удалённые задачи. Незавершённые наборы нельзя начать или подключить в очередь; уже открытое прохождение остаётся доступно. Последний локальный черновик остаётся до подтверждённого сохранения. Конфликт другой вкладки останавливает автозапись без перезаписи чужой версии. Ручное сохранение не закрывает редактор.
- Вставка нескольких ответов поддерживает пробелы, табуляцию и переносы строк с текущего поля. №25 заполняется в порядке видимых строк двухколоночной таблицы. Самостоятельные вопросы идут по номерам; уже верные поля не перезаписываются.
