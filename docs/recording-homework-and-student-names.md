# Recordings as homework and unique student names

Teachers can select an existing private lesson recording in the individual or group homework composer under **Записи занятий**. The library includes all ready recordings owned by the teacher, independently of the latest-twelve list used by recording settings. It searches titles, participant names and dates. Transcript search stays in the local recorder; the composer opens its archive with the search query and recipient. Recorder 1.4.2 defaults to the whole lesson and also offers explicit fragment boundaries. A ready whole lesson reuses its private Rutube URL, while a local-only whole lesson is remuxed and a fragment is exported to MP4 before publishing.

**Задать в домашку** in the recorder opens the platform with the material selected and, when supplied, the recipient. The teacher still reviews and submits the ordinary composer. Video homework without quiz questions gets the existing player and a **Посмотреть** checklist item. Regular video authoring continues to require a quiz. Recorder metadata is accepted only through trusted server options; client payloads cannot bypass that requirement. Student projections omit the source recording identity. Assigning the video does not grant access to the other student's lesson history or other materials.

`GET /api/lesson-recording-library` and `POST /api/lesson-recording-library/:id/material` use staff authentication and teacher ownership. Repeated conversion reuses an active video material by URL. Re-adding a deleted material creates a new identity instead of resurrecting old assignments. The local archive keeps sources, transcripts and credentials on the computer.

The teacher's student creation form checks both primary name and **Имя 2** after 250 ms of typing and disables creation until the latest request succeeds. `POST /api/students/name-availability` reports occupancy without exposing account identities. The server checks both fields across all teachers, including accounts within their restoration period, with normalized case, whitespace, Unicode and е/ё. An occupied main name requires a free second name; an occupied second name blocks creation. Creation repeats the check immediately before writing, and name changes apply the same rule excluding the edited account. Other edits to legacy duplicate accounts remain possible.

Validation: 84 automated tests across the recording/homework integration, name conflicts and concurrent creation, material ownership/idempotency/deletion, group homework, desktop recording lifecycle, archive publishing/whole lessons, package integrity, updater and frontend API requests. Production build passes the existing initial-bundle budget. Targeted lint passes; server/index.js retains its 41 pre-existing lint errors and introduces none. Browser checks used isolated application data for live name feedback, teacher conversion and assignment, student checklist completion, transcript search, full/fragment selection and the recorder-to-composer handoff. Synthetic media and stub publishing were used in archive UI tests; no real student was assigned test homework.
