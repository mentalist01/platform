# Переход ученика к новой задаче

«Следующее», «Пропустить», открытие из списка и вставка из пробника публикуют команду фокусировки в существующем поле `theoryFocus`. Название поля сохранено для совместимости с уже установленным клиентом теории. Команда меняется только при явном переходе, несёт ID карточки и возрастающую ревизию. Доставка идёт через существующий Yjs-сигнал; новых интервалов и запросов на каждом кадре нет. Другие окна учителя, домашка и режим просмотра остаются независимыми.

При автооткрытии после решения маркер содержит `afterSolve`: ученик, находящийся на решённой задаче, сначала видит прежнее поздравление, затем плавно переходит дальше. Ученик, смотревший другую задачу, переходит к общей новой задаче. Обычное изменение ответа, кода, файлов, размеров, режима и переключение вкладки учителем не создают команды. При первом подключении старый переход не воспроизводится.

Вставка старых карточек из тестирования отслеживается по вставленным значениям дельты Yjs: только новая задача преподавателя, только после завершения синхронизации, только у ученика. Замена существующего объекта при вводе ответа, первоначальная загрузка, переподключение, рисунки и изменения других учеников не двигают камеру. Используется общая функция плавного перехода, учитывающая локальную ширину экрана и масштаб.

Вставка из пробника получает отдельную ревизию после добавления карточки: сигнал предварительного добавления в очередь больше не может поглотить окончательное обновление.

Проверено 75 тестов и ESLint без ошибок (предупреждения в App.jsx существовали ранее). В двух независимых фоновых вкладках проверены реальные PreparedLessonBoard, usePreparedLesson и WebSocket-доставка: ученик отошёл на y=6000; проверка ответа не вернула его; «Следующее» плавно переместило к задаче 2; повторный уход и «Пропустить» переместили к задаче 3. Сохранён снимок конечного вида ученика.
