# Очистка диска и перенос архивов в S3 · 29 октября 2026

Рабочий диск и S3 — разные хранилища. Платформа уже использовала бакет `ivan100-lesson-recordings` для нового аудио, но локальные архивы обслуживания и временные каталоги выпусков оставались на основном диске.

Измерено до основной очистки (GiB, округление):

| Категория в /root | Объём |
| --- | ---: |
| Временные каталоги выпусков `*-stage` | 8.43 |
| Отдельные каталоги отката `*-backup` | 2.30 |
| Архивы обслуживания | 8.93 |
| Материалы `/root/platform-uploads` | 3.31 |
| Данные `/root/platform-data` | 2.35 |
| Рабочая копия `/root/app` (включая dist, Git, зависимости и старые вложенные данные) | 6.85 |
| Остальные каталоги /root, в том числе старые этапы с датой в конце имени | 7.87 |
| **Всего /root** | **40.04** |

Вне /root отдельно находятся ОС/библиотеки `/usr`, журналы и служебные данные `/var`, временные файлы `/tmp`, настройки `/etc` и служебные блоки файловой системы. Полная финальная сумма измеряется после завершения фоновых операций; суммировать размеры во время удаления некорректно. Timeweb и `du` также могут показывать разные единицы и обновлять график с задержкой.

`scripts/archive-maintenance-to-s3.mjs` переносит только закрытые обычные файлы `.tar.gz`/`.tgz` старше суток из фиксированного каталога архивов. Перед переносом проверяется запрет анонимного чтения синтетического приватного объекта. Крупные файлы загружаются частями с Content-MD5, затем полностью скачиваются потоком для сверки SHA-256. Размер/mtime/inode источника должны остаться прежними. Журнал восстановления сбрасывается на диск до удаления локальной копии. При ошибке локальный архив сохраняется, незавершённая загрузка отменяется. Ключи доступа берутся из существующего процесса PM2, в отчёты не попадают. Скрипт не удаляет объекты S3 и не меняет тариф/права бакета. Порог суммарного объёма перед переносом — 85 GiB.

Восстановление локального архива:

```
cd /root/app
node .maintenance/archive-maintenance-to-s3.mjs --restore <имя-архива.tar.gz>
```

Создание существующего файла запрещено. Скачанная копия проверяется по сохранённой SHA-256 и длине. Карта объектов находится в `/root/ivan100-maintenance-archives/s3-verified-transfers.jsonl`. Основной префикс S3: `maintenance-archives/verified-v1/`.

`scripts/clean-generated-release-stages.mjs` удаляет только проверенные повторно хешами файлы временного выпуска. Для исходников требуется точное совпадение с Git-объектом из commit в manifest; для собранных файлов — SHA-256 из manifest. Неизвестные файлы, изменённые исходники, переходы по ссылкам и пути вне разрешённой структуры останавливают очистку соответствующей папки. Полная квитанция удаления записывается до удаления кэша. Последние три каталога и выпуски моложе суток сохраняются. Каталоги отката, база и материалы не входят в эту очистку.

Сервис `ivan100-storage-maintenance` запускает эти две операции ночью, в 04:20 по Москве с задержкой до 10 минут. Приоритет CPU/диска понижен; ограничение CPU 50%, память 512 MiB. Публикация новых пакетов дополнительно удаляет собственные временные исходники и артефакты после завершения проверок, сохраняя manifest, результаты проверок и отдельную копию для отката.

Проверка утилит: 7 тестов — успешный перенос, проверка полной копии, повреждённое скачивание, прерывание multipart, запрет изменённых исходников/выхода из каталога, изменение файла после аудита и сохранность посторонних файлов. Реальный перенос дополнительно проверяет каждый архив полным чтением из S3.

Один архив реально восстановлен по журналу; его размер и хеш совпали. Из 61 старого проверенного каталога выпуска удалено 7.541160 GiB (около 8.10 GB) воспроизводимых файлов. Последние выпуски, отдельные копии отката, база и пользовательские материалы сохранены. Итого основные две операции освободили около 17.68 GB. Ранее отдельно удалены проверенные дубликаты зашифрованных пакетов.

## Старые каталоги выпусков и отката в S3

По отдельному согласованию старые целые каталоги `*-stage[-…]`, `*-backup[-…]` и `dist.before-*` переносятся утилитой `scripts/archive-old-release-directories.mjs`. Работающие `/root/app`, `/root/platform-data` и `/root/platform-uploads` исключены. Нераспознанные каталоги также исключены. Сохраняются две самые свежие папки каждого типа, все папки моложе суток, используемые процессами каталоги и любые каталоги, внутри которых недавно менялись файлы. Маленькие папки с квитанциями остаются локально.

До архивации сохраняется инвентаризация всех файлов, SHA-256, типов, прав и символьных ссылок без перехода по ним. Закрытый tar.gz сравнивается с исходным каталогом. После загрузки приватного объекта выполняются полное чтение и сверка SHA-256, затем отдельное скачивание, распаковка и сверка всех восстановленных файлов. После повторной проверки неизменности и отсутствия активных процессов журнал восстановления принудительно сбрасывается на диск. Только затем удаляются исходный неактивный каталог и временный локальный архив. При любой ошибке источник остаётся.

Карта восстановления: `/root/ivan100-release-directory-transfers.jsonl`; полная инвентаризация хранится в записи `verified-before-removal`. Поздняя запись `removed-local` не заменяет инвентаризацию. Полная квитанция также сохраняется приватно на S3 рядом с архивом (`.inventory.json`), с SHA-256 и проверкой полного чтения. Для восстановления без перезаписи работающей версии:

```
cd /root/app
node .maintenance/archive-old-release-directories.mjs --restore <имя-старого-каталога>
```

Проверенный результат появляется в `/root/ivan100-release-restore/<имя-старого-каталога>`. Повторная запись существующего каталога запрещена. Если локальная карта утрачена, квитанция автоматически ищется в S3; флаг `--remote-index` принудительно проверяет восстановление по удалённой карте. Переключение работающей платформы на восстановленную версию — отдельная операция.

Ночной сервис сначала удаляет воспроизводимый кэш по manifest, затем архивирует закрытые старые целые каталоги, затем переносит оставшиеся обычные архивы обслуживания. Минимум две свежие копии сохраняются локально; возрастной запас в сутки защищает подготовку текущих выпусков. Тесты утилит: 14 успешных проверок, включая сохранение свежих копий, запрет защищённых путей, подмену содержимого при сохранённых времени и размере, повреждённое восстановление, выбор полной квитанции и проверку приватной удалённой карты восстановления.
