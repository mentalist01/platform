# Перенос изображений доски

Новые изображения доски хранятся отдельными файлами, а в Yjs остаются короткие ссылки. Старые Base64-изображения можно проверить без записи и затем перенести с автоматической резервной копией.

## Проверка без изменений

Команду нужно запускать с теми же каталогами данных, которые использует сервер:

```bash
PLATFORM_DATA_DIR=/root/platform-data \
PLATFORM_UPLOADS_DIR=/root/platform-uploads \
PLATFORM_COLLAB_DIR=/root/platform-collab \
npm run board-assets:migrate
```

В результате `blockedSnapshots` должен быть пустым, а `unmatchedSnapshotCount` — равен нулю. Этот режим ничего не записывает.

## Применение

1. Закрыть доски во всех открытых вкладках преподавателя и учеников.
2. Остановить backend, чтобы старое состояние Yjs не записалось поверх результата.
3. Повторить сухую проверку.
4. Запустить перенос с теми же переменными окружения:

```bash
PLATFORM_DATA_DIR=/root/platform-data \
PLATFORM_UPLOADS_DIR=/root/platform-uploads \
PLATFORM_COLLAB_DIR=/root/platform-collab \
npm run board-assets:migrate:apply
```

Скрипт откажется продолжать при заблокированных или неизвестных снимках. Перед записью он сохранит исходные снимки и реестр изображений в каталоге `migration-backups`, путь к которому напечатает в результате.

После переноса нужно запустить backend, открыть одну из перенесённых досок и проверить отображение старых изображений и вставку нового изображения из буфера обмена.
